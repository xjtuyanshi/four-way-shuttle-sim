2026-05-31: Protect Active Inbound Fill Columns From Empty Pickup Traffic

Core routing · agent-refresh · top-lift-column-v1

What Changed

Empty inbound pickup shuttles can no longer use a column as a transit corridor while another loaded inbound shuttle is actively filling that same column. If an empty shuttle starts inside that active column, only its current node and safe side exits remain usable; the rest of the column stays protected.

Why It Matters

The 3991s failure pattern was a reciprocal claim at storage-r01-c19 and column-top-b-c19: an empty shuttle tried to exit upward through the same column that a loaded shuttle was entering to fill. That is a traffic-rule error, not a visual problem.

2026-06-01: Convert Repeated Gridlocks Into Explicit Traffic Rules

Core routing · reciprocal swaps · column access · 12h audit

What Changed

The latest fix moves several repeated deadlock shapes out of ad hoc local avoidance and into explicit agent-refresh rules. Reciprocal storage swaps, column-access/storage swaps, taskless no-stop waits, and blocked same-column exits are now detected directly and cleared before the deadlock smoke detector has to escalate.

Why It Matters

These failures were not independent visual glitches. They were missing traffic invariants: a shuttle could wait on a no-stop access node, two shuttles could target each other's cells, or a later inbound load could enter a column before its deeper predecessor was physically reachable. The fix makes those states illegal or self-clearing in the core model.

Waiting/blocked vehicle Legal grid / loaded vehicle Conflicting target or no-stop hold New legal clearance action

Root Logic Changes

agent-refresh now proactively clears reciprocal storage swaps, column-access/storage swaps, taskless no-stop waits, and same-column storage exit blockers.

Inbound pickup dispatch now waits when a deeper same-column predecessor has not physically reached its dropoff, preserving column-fill reachability.

After ChatGPT Pro review, local clearance routes also reject any route node that is already reserved by another shuttle within the route travel window. A legal hold must be claimable before a breaker starts.

2026-06-01: Live Browser 5:15 / 6:12 Gridlock Investigation

Runtime process audit · stale API restart · targeted live repro

What Happened

The browser was still connected to an API process started around 3:00AM, before the latest gridlock fixes were loaded. That stale process reached a real stuck state: SH-03 and SH-07 parked on the inbound pickup spines with inbound-source-not-at-pickup, while their source pallets were still in buffer slot 02. The following shuttles then formed long wait chains behind them.

Why The Earlier Audit Missed It

The 12h audit used a fresh in-process SimCore instance from the current source tree. The live browser was not using that instance; it was using the stale long-running API server. The right lesson is that future validation must include a live API/browser run after server restart, not only a headless core run.

2026-06-01: Separate Pickup Targets From Shuttle Labels

2D readability · pickup marker semantics · route overlay cleanup

What The Circle Was

The round numbered marker near outbound-left storage was a dashboard pickup target marker, not a physical shuttle and not a waypoint where the shuttle should hover. It used the assigned vehicle number, so it looked too much like a vehicle and obscured the real route line.

Display Change

Pickup targets now render as small P# labels offset from the track with a thin leader line back to the exact pickup node. Shuttle bodies keep the direction arrow inside the square, while the shuttle number moves to a separate corner badge so the label and arrow do not overlap.
